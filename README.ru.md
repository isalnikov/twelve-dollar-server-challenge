# Сервер за двенадцать долларов

Реализация задания [twelve-dollar server challenge](https://github.com/arjaythedev/twelve-dollar-server-challenge) на Java 25 и Netty: пять HTTP-ручек, SQLite, JWT HS256 и запись, которая переживает сбой процесса. Процесс слушает порт сам. Nginx из конфига задания ограничен `worker_connections 16384` и на одном ядре забирает заметную долю CPU, поэтому 40 000 keep-alive соединений за ним не помещаются.

English: [README.md](README.md). Замер: [RESULTS.ru.md](RESULTS.ru.md), [RESULTS.md](RESULTS.md).

## Ручки

| Метод | Путь | Токен | Ответ |
|---|---|---|---|
| GET | `/health` | нет | `{"status":"ok","db":"ok","uptime_s":N}` или 503, если SQLite не отвечает |
| GET | `/feed` | нет | 20 свежих постов, `created_at DESC, id DESC` |
| GET | `/posts/:id` | нет | один пост, либо 400 / 404 |
| POST | `/posts` | bearer | 201 и сохранённый пост |
| POST | `/posts/:id/like` | bearer, проверяется раньше id | 201 в первый раз, 200 при повторе, 404 если поста нет |

Ключи JSON идут в порядке `id`, `body`, `created_at`, `author`, `like_count`. Ошибки — `{"error":"..."}`. Тело поста обрезается набором пробелов JavaScript и должно быть от 1 до 500 символов. JWT — HS256, секрет `twelve-dollar-challenge`, `sub` — строка с положительным целым, `username` — строка, `exp` — секунды. Кэша ответов и кэша токенов нет.

## Как идёт запрос

Один поток event loop принимает соединение, разбирает байты, ходит в SQLite и пишет ответ. Второй поток раз в секунду делает `PRAGMA wal_checkpoint(PASSIVE)` на своём соединении. Пул потоков на одном ядре машины задания только добавлял бы планировщик.

Две таблицы фиксированного размера, обе на 65 536, обе степень двойки:

- **Слоты.** Пока на соединении тишина, оно занимает только номер слота. Живой список упорядочен по последней активности, голова — самое давно молчащее. Когда число слотов доходит до потолка дескрипторов (`min(60000, RLIMIT_NOFILE - 1024)`), закрываются keep-alive, которые молчат дольше секунды. Клиент откроет новое соединение на следующем запросе. Один и тот же молчащий слот не выбирается дважды.
- **Кольцо.** `channelRead` только дописывает байты и кладёт индекс слота. После текущего прохода `select` метод `drain` разбирает все накопившиеся соединения. Все `INSERT` этой пачки идут в одном `BEGIN IMMEDIATE` … `COMMIT`. Ответ на запись держится в памяти, пока коммит не прошёл. Неудачный коммит откатывается, клиенту уходит 500, соединение закрывается.

HTTP/1.1 разбирает `Http` (заголовки до 8192 байт, тело до 16384). Чтение просит у SQLite `json_object(...)`, поэтому лента уже JSON. Вставка использует `RETURNING` и небольшой сборщик в Java, чтобы кавычки в теле были экранированы. SQLite — амальгама 3.54.0, вызовы через FFM, не JDBC. Прагмы: WAL, `synchronous=NORMAL`, внешние ключи, `busy_timeout=5000`, mmap 256 МБ, кэш 32 МБ, временные данные в памяти, `wal_autocheckpoint=0`.

На Linux цикл — epoll (`EpollEventLoopGroup`, нативные сборки `linux-x86_64` и `linux-aarch_64`). Принятым сокетам ставятся `TCP_NODELAY`, `TCP_QUICKACK` и `TCP_NOTSENT_LOWAT` в 32 КБ. В Netty 4.2 `EPOLL_MODE` не переключается. `SO_BUSY_POLL` и `TCP_CORK` не включены: на одном vCPU они занимают ядро и задерживают короткий ответ. `install.sh` ставит `somaxconn` 8192, выключает slow-start после простоя и поднимает предел дескрипторов до 65535. На этом Mac epoll нет, поэтому эти опции не входят в измеренные 10 677 зап/с на смеси (см. RESULTS.ru.md). JVM: Serial GC, куча 512 МБ с предварительным касанием, компактные заголовки объектов, поиск утечек Netty выключен.

## Сборка и запуск

`build.sh` скачивает амальгаму, сверяет SHA3-256 `7b670a62fdfbd672b75fef004cb703c8a3e87d3a5cc7d675b4a08337004a2d93`, собирает `native/libsqlite3` и пишет `target/cp.txt`. В jar нет классов Netty, поэтому `start.sh` подставляет этот classpath. На чистой Ubuntu 24.04 один раз от root: `bash install.sh`.

```bash
bash build.sh
SQLITE_PATH=seed/feed.db JWT_SECRET=twelve-dollar-challenge HOST=127.0.0.1 PORT=3000 bash start.sh
```

Тесты, включая интеграционные на временной базе:

```bash
mvn test
```

Пятиминутные прогоны, разбор на месте и сравнение SQL ленты — в [RESULTS.ru.md](RESULTS.ru.md). Профиль JVM и JEP 520: [PROFILE.ru.md](PROFILE.ru.md). Цикл на чистом `java.nio` — `TRANSPORT=nio`; на этом Mac за пять минут быстрее Netty. Опционально: `PROFILE=1` или `TIMING=1` с `bash load.sh`.

Пять минут нагрузки (отдельный процесс сервера, закрытый цикл, без пауз):

```bash
bash load.sh
```
